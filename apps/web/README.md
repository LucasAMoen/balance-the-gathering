# Web App

## Web App Project Structure

``` md
src/
  app/                                #The actual routing and pages of the application
    routes/
      app/                            #Pages of the application after auth
      auth/                           #Pages of the application before auth
        login.tsx
        register.tsx
    index.tsx
    provider.tsx
    router.tsx
  features/                           #Any new feature for the application goes here
    <feature>/                        #Feature directory
      types/
        example/types.ts
      api/
        getExample.ts
      data/                           #Mocks data if necessary
        exampleMockData.ts
      hooks/                    
        useExample.ts
      components
        ExampleComponent.tsx
  components/                         #Reusable components between features
    ExampleComponent.tsx
  hooks/                              #Global utility hooks
    useExample.ts
  api/                                #Api calls from endpoints used in multiple features
    getExample.ts
  data/
    exampleMockData.ts                #Mock data if necessary
  types/
    api.ts                            #Should be autogenerated from api openapi definitions
  constants/
    example.ts
  lib/
  theme/                              #Used to manage all theme related things of the application
    colors.ts
    typography.ts
    spacing.ts
    themes/
      dark/
      light.ts
      magic.ts
    index.ts
  providers/
    ExampleProvider.tsx
    ThemeProvider.tsx
```

## Application Patterns

### MVP
- View layer
  - components, screens, UI logic
- Presentation layer
  - Custom hooks, business logic, state managment
- Model
  - API client, Storage, Auth, external dependencies, mock data

View -> Presenter -> Model

## Tech Stack

- Motion - animation library
- Material UI (MUI) - standard component libary
- React Router - routing library for app navigation
- Tanstack Query - Caching and invalidating data from api calls
- Axios - API client that allows for custom api clients
- Jest - Testing library

## Expanding the ESLint configuration

If you are developing a production application, we recommend updating the configuration to enable type-aware lint rules:

```js
export default defineConfig([
  globalIgnores(['dist']),
  {
    files: ['**/*.{ts,tsx}'],
    extends: [
      // Other configs...

      // Remove tseslint.configs.recommended and replace with this
      tseslint.configs.recommendedTypeChecked,
      // Alternatively, use this for stricter rules
      tseslint.configs.strictTypeChecked,
      // Optionally, add this for stylistic rules
      tseslint.configs.stylisticTypeChecked,

      // Other configs...
    ],
    languageOptions: {
      parserOptions: {
        project: ['./tsconfig.node.json', './tsconfig.app.json'],
        tsconfigRootDir: import.meta.dirname,
      },
      // other options...
    },
  },
])
```
